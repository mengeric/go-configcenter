# 实战避坑指南 (Pitfalls & Gotchas)

本文档记录在微服务接入、配置中心通信、网络与容器化部署过程中的关键实战陷阱。

---

## 1. 注册 IP 陷阱：Docker 网桥与虚拟网卡

### 现象
服务在容器中使用 `--net=host` 或直接在宿主机部署时，注册到 Nacos 上的 IP 变成了 `172.17.0.1`（`docker0` 地址），导致跨节点调用网络不通。

### 根因
简单遍历系统网卡容易按字母序直接选取首个非回环网卡，而宿主机上的 `docker0` / `veth*` / `br-*` 网卡也是非回环的。

### 规避方案
1. 始终使用 `netutil.ResolveRegisterIP`；
2. 优先通过 `HOST_IP` / `POD_IP` 环境变量注入真实外部 IP；
3. 本地探测时使用目标注册中心 UDP 出网嗅探判定实际出网网卡。

---

## 2. 环境变量展开与默认值

### 现象
使用 `${VAR:-default}` 语法时，若 `VAR` 存在且为空字符串（`VAR=""`），由于语法解析差异，可能误用空字符串而非默认值。

### 规避方案
SDK 中的 `expandEnv` 严格遵循 POSIX 规则：当环境变量未设置时回退默认值；当需确保非空时，可在应用入口做非空校验。

---

## 3. Nacos 动态订阅闭包与内存泄露

### 现象
多次重复调用 `WatchConfig` 或未释放订阅，导致回调函数闭包常驻内存，频繁触发回调冲突。

### 规避方案
使用 SDK 统一提供的 `s.Subscriber()` 单例驱动，避免业务层绕过 SDK 直接频繁注册低级 Watcher。

---

## 4. 动态服务发现未订阅与全下线 Panic 陷阱

### 现象
1. 业务调用 `s.Discover()` 时，下游实例发生缩容或重启后，调用方仍然持有已销毁实例或未更新实例，动态发现未生效；
2. 当下游服务所有实例下线时，负载均衡选机直接切片越界 panic。

### 根因
1. 服务发现只执行了单次拉取，未向 Nacos 注册动态订阅通道；
2. 加权轮询（WRR）代码中未对空健康列表进行防御性拦截，直接执行 `instances[0]`。

### 规避方案
1. 采用**首次发现即自动订阅**（Lazy Auto-Subscribe）机制，确保目标服务在首次 Discover 时同步拉取健康实例并建立后台动态推送通道；
2. 加权轮询前严格校验可用实例切片长度，若无可用实例返回明确的错误，禁止直接数组索引；
3. 需要长期维护连接池的场景，通过 `s.Subscribe(serviceName, callback)` 接入动态监听。
